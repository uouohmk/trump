# 운세·사주·궁합 기록 지침

인물별 출생 정보와 계산 조건을 기준으로 서양 점성술·사주명리 해석을 연결하고, 관계별 기록과 실제 사건을 시간순으로 축적한다. 기존 기록이 있으면 그 파일의 구조와 식별자를 우선 유지한다. 실제 인물이 제공되지 않았다면 빈 양식을 제공하고 인물을 만들어 채우지 않는다.

## 1. 세 가지 층위

| 층위 | 내용 | 기록 원칙 |
|---|---|---|
| 입력·역법·천문 | 사용자가 제공한 출생 정보, 달력 변환, 절기·천체 위치 | 원입력과 변환값, 출처·계산 조건을 함께 보존 |
| 전통 해석 | 사주 원국·운의 주기·궁합, 서양 출생 차트·트랜짓·시너스트리 | 체계·유파·해석 근거·풀이 시점을 표시 |
| 생활 기록 | 당사자가 보고한 관계·선택·실제 사건 | 사건 발생일과 기록일, 보고자를 구분 |

사주는 출생 연·월·일·시를 천간·지지로 나타내는 전통이다. 서양 점성술의 행성 위치·황도궁과 같은 계산 체계로 취급하지 않는다. 사주에서 음양·오행·합충 등을 해석에 사용하는 역사적 설명은 [한국민족문화대백과사전 「사주」](https://encykorea.aks.ac.kr/Article/E0025957)를 참고한다. 이 자료는 문화적 체계의 설명이며 예측력의 입증 자료가 아니다.

음양력 변환·절기 자료의 출처로 [KASI 생활천문관의 OpenAPI 안내](https://astro.kasi.re.kr/life/pageView/31)를 활용한다. 역법 자료가 정확하다는 사실이 사주·궁합 해석의 과학적 정확성을 보증하지는 않는다. 위 출처 확인일: 2026-09-12.

## 2. 인물과 관계의 식별

- 실명 대신 별칭과 고유 인물 ID를 사용할 수 있다. 같은 이름이라는 이유만으로 두 기록을 합치지 않는다.
- 사람별로 출생 정보를 한 번 저장하고, 관계 기록에서는 인물 ID를 참조한다.
- 관계 유형은 사용자가 알려 준 연인·배우자·가족·친구·동료·기타를 사용한다. 두 사람이 연인이라고 추정하지 않는다.
- 원래 사용자 서술, 다른 사람의 보고, 모델의 해석을 구분한다. 출생 정보나 궁합으로 상대의 실제 감정·의도·정신건강 상태를 확정하지 않는다.
- 파일 저장을 요청받으면 지정된 파일을 갱신한다. 저장 도구가 없으면 붙여 넣을 기록을 제공하고 저장했다고 말하지 않는다. 별도 요청 없이 외부에 전송하거나 장기 메모리에 등록하지 않는다.

## 3. 출생 정보와 누락 처리

필요한 입력은 출생일, 양력/음력, 음력의 윤달 여부, 출생시각과 정확도, 필요한 경우 출생 도시·국가 및 당시 시간대다. 원문 표현을 보존한 다음 변환값을 따로 적는다. 주소 전체는 보통 필요하지 않다.

출생시각이 없으면 미상으로 둔다. 임의의 정오를 실제 출생시각으로 저장하지 않는다. 원국의 시주와 상승궁·하우스는 확정하지 않으며, 경계에 영향을 받는 다른 요소도 조건별로 처리한다. 사용자 자료의 사주팔자가 이미 있으면 사용자 제공값으로 보존하고 독립 계산·검증 여부를 표시한다.

성별 관련 입력이 특정 유파의 대운 순역 규칙에 실제로 필요한 경우에만 해당 규칙과 함께 확인한다. 이름·외모·관계 역할로 추정하지 않는다. 입력이 없으면 영향을 받는 부분만 미정으로 두고 나머지 기록은 작성한다.

## 4. 사주 계산 조건

만세력·계산 도구를 사용하기 전에 다음 조건 중 실제 결과에 영향을 주는 항목을 기록한다.

| 항목 | 확인할 내용 |
|---|---|
| 달력 변환 | 원입력 양력/음력·윤달, 변환 출처·적용 범위 |
| 연주 경계 | 선택 유파의 입춘 등 연 경계와 적용 시각 |
| 월주 경계 | 월을 구분하는 절입 기준·시각; 음력 월 숫자로 단순 대입하지 않음 |
| 일주 경계 | 자정/자시 등 날짜 변경 규칙, 역일 계산 기준 |
| 시주 | 시각 구간, 표준시/지역 태양시 등 보정 여부 |
| 대운 | 순역 규칙, 기산에 쓴 절기, 시간 차이·환산 방식 |
| 재현 정보 | 도구·버전·계산일, 입력값, 선택 조건, 결과 출처 |

경계 부근이면 출생시각 불확실성과 계산 규칙 차이를 별도로 비교한다. 근거 없이 한 결과를 정답으로 선택하지 않는다. 신뢰할 도구나 기존 원국이 없으면 계산 보류로 표시한다. GitHub의 케플러·평면 궤도 예제는 사주 만세력 도구가 아니다.

원국에는 연주·월주·일주·시주와 일간을 기록한다. 오행·십성·지장간·합충형해·격국·용신 등은 실제 요청한 수준에서 추가하고, 유파별 판단이 갈리는 항목은 해석으로 표시한다. 단순 오행 개수만으로 강약이나 용신을 확정하지 않는다.

### 사주 심층 분석을 덧붙일 때

[사주 심층 연구](saju-divination-research.md)와 [해석 절차](saju-interpretation-protocol.md)를 필요한 범위에서 읽는다. 기존 원국·인물 ID를 유지하면서 다음을 추가한다.

- 문헌·판본·해석 경로, 규칙 세트와 확인일.
- 천간·지지의 대표 배속·지장간을 구분한 구조와 십성.
- 월령·통근·투간, 강약 판단의 근거와 반대 조건.
- 격국 후보와 성립·훼손·구응 조건.
- 용신이라는 말을 쓰는 뜻, 후보·근거·상신·희기·대안.
- 합충 등의 조합 확인과 실제 작용 판정의 구분.
- 사용한 경우 신살·십이운성의 기준과 보조적 해석.
- 원문 용어와 정규화 용어가 다른 경우의 대응·교정 이유.

계산이 미정인 항목에 의존하는 결론은 조건부 또는 보류로 둔다. 풀이에 새 문헌이나 다른 유파를 적용할 때 기존 결론을 지우지 않고 해석 버전을 추가한다. 특정 글자를 질병·사망·배우자의 의도 같은 실제 사실로 변환하지 않는다.

향후 DB·사이트 출력용으로 옮길 때도 계산 상태·해석 체계·버전·불확실성을 결과와 함께 유지한다. 여기의 기록 구조를 제안한 것과 실제 외부 서비스를 구현한 것을 구분한다.

## 5. 서양 점성술과 연결

서양 차트는 기존 SKILL.md의 역서·좌표·시간 기준을 따른다. 회귀/항성 황도대, 아야남사, 하우스, 애스펙트 허용각을 기록하고 출생시각에 민감한 값은 별도 표시한다.

통합은 동일한 인물·질문·기간을 기준으로 두 해석을 나란히 놓는 방식으로 한다.

| 사주 해석 | 서양 점성술 해석 | 통합 기록 |
|---|---|---|
| 원국의 전통적 성향 해석 | 출생 차트의 상징 해석 | 유사한 주제·차이·확인할 생활 질문 |
| 대운·세운·월운 등 | 특정 기간의 트랜짓 등 | 각 기준의 기간 시작·종료·불확실성 |
| 두 원국의 관계 해석 | 시너스트리 등 | 대화·갈등·협력 주제와 실제 경험 |

오행과 행성, 십성과 별자리 사이에 일대일 물리 대응을 만들지 않는다. 서로 비슷한 표현이 나와도 예측의 독립 검증으로 세지 않는다. 체계가 충돌하면 충돌을 남기고 평균 점수로 지우지 않는다.

## 6. 운세와 궁합 서술

- 개인 운세에는 대상 인물, 질문, 기간, 사용 체계, 입력의 확실성을 먼저 기록한다. “올해·다음 달”은 작성 시점을 기준으로 실제 연월이나 날짜 범위로 바꾼다.
- 사건이 반드시 생긴다는 단정 대신 해당 전통에서 제시하는 주제·가능한 해석·현실에서 확인할 질문으로 서술한다.
- 궁합은 두 사람의 관계 맥락에 맞춰 소통·갈등 처리·생활 리듬·협력 방식을 설명한다. 한쪽의 진술을 두 사람 모두의 확정 사실로 기록하지 않는다.
- 궁합만으로 결별·결혼·채용 같은 결정을 확정하거나 질병·사망·재정 결과를 사실처럼 예언하지 않는다. 현실적인 선택 조언에는 당사자의 의사·관찰된 행동·실제 조건을 우선한다.
- 점수는 기본 출력에 넣지 않는다. 요청하면 산정 규칙이 공개된 참고 지표로 표시하며 관계 성공 확률이나 검증된 정확도처럼 표현하지 않는다.

## 7. 기록과 갱신

인물, 관계, 풀이, 사건에 각각 식별자를 부여하고 연결한다. 새 항목의 ID가 기존 것과 겹치지 않도록 현재 파일을 확인한다.

풀이에는 작성일·대상기간·당시 알고 있던 정보·체계·해석을 남긴다. 사건에는 실제 발생일·기록일·보고자·관련 풀이 ID를 남긴다. 해석을 사후에 고치면 기존 내용과 수정 이유를 보존하여 예측이 처음부터 맞았던 것처럼 만들지 않는다.

나중의 평가 상태는 미평가/부합/불부합/혼합/판단 불가로 구분할 수 있다. 자료가 없다는 것은 부합이 아니다. 적중한 사례뿐 아니라 빗나감과 애매한 결과도 남긴다. 개인 일지를 통제된 과학 실험이나 예측력 증명으로 제시하지 않는다.

출생 정보가 바뀌면 기존 계산을 덮어쓰는 대신 새 버전을 만들고, 영향을 받는 풀이를 재검토 필요로 표시한다. 변경된 인물이 포함된 관계 기록도 함께 확인한다. 과거 사건 기록 자체를 새 해석에 맞춰 바꾸지 않는다.

[기록 양식](../assets/fortune-record-template.md)을 시작점으로 사용하되 사용자의 기존 형식을 불필요하게 교체하지 않는다. 새 기록에는 필요한 구역만 작성한다. 실제 인물이 제공되기 전까지 빈 양식은 실존 인물 기록으로 취급하지 않는다.
